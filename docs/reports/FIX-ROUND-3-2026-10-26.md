## Item 1 — Client horse-add, regression R1

**DONE.** `horses.injuries_to_humans` was `text NOT NULL` with no default (disc_21),
but both writers (`create_horse_record`, `update_horse_record`) insert
`nullif(btrim(coalesce(p->>'injuries_to_humans','')),'')` → NULL when no injuries
answer is given — i.e. every normal create — so the insert 400'd.

Migration `fr_20261026T1000_item1_injuries_nullable.sql`:
- `ALTER TABLE horses ALTER COLUMN injuries_to_humans DROP NOT NULL`.
- Normalized the six existing `''` rows (disc_21 backfill) to NULL so "unanswered"
  is one value everywhere.

NULL means the question has not been answered: the record hides the line (HorseRecord
`{!!r.injuries_to_humans && …}`), never renders "None"; the contract gate
`HORSE.INJURIES_TO_HUMANS_GATE` mirrors it as empty (`horse_field_token_value`
returns `''`), and an empty required selector keeps the document unsignable
(`contract_lock_blockers`). None is the maker's explicit YES/NO/UNKNOWN choice.
No reader needed changing — all of `horse_page_detail`, `horse_field_token_value`,
`sync_horse_documents` already coalesce NULL to blank/empty.

**DB proof (rolled back):** `create_horse_record` with no injuries answer now
returns `{"outcome":"created"}` as the client test contact (previously 23502 NOT
NULL). The item-2 lease proof below also shows the gate listed as a signing blocker
("Injuries to humans — anything to disclose?") when unanswered.

Browser proof: consolidated with item 4 (onboarding horse-add, staff add-horse modal,
lease gate) — see item 4.

## Item 2 — Signature primitive, regression 6a

**DONE.** Migration `fr_20261026T1010_item2_blocker_in_record_signature.sql`.

**Callers.**
- `record_signature(uuid,text,text,text,text,boolean)` — DB callers: only
  `lock_and_sign_contract`. Code callers: `src/lib/api.ts:recordSignature`,
  `src/lib/ops/api-client.ts` (two wrappers) → SigningPanel, SignPartyRow,
  Onboarding.
- `lock_and_sign_contract(uuid,text,text,boolean,text)` — DB callers: none. Code
  callers: `src/lib/contracts.ts:lockAndSign` → ContractPage.

**Change.** The `contract_lock_blockers` check moved from `lock_and_sign_contract`
into `record_signature`, placed after the signer-role and typed-name checks and
before the signature INSERT, so a document with a non-empty blocker set is refused
through EVERY caller. A document with no required fields and a named signer returns
`[]` and passes unchanged (flat onboarding docs have no `contract_fields` rows).
The entity capacity fields `lock_and_sign_contract` writes still land first, because
it calls `record_signature` last. `lock_and_sign_contract` no longer runs the check
itself — one implementation of the gate.
